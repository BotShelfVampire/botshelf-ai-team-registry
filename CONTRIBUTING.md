# Contributing to the BotShelf Vampire Build Library

This repository is the public source for the **Build Library**: local and self-hosted AI workflow building blocks. It is separate from the ready-to-use Marketplace.

Useful contributions make one job easier to run, inspect, or adapt:

- correct an instruction, prerequisite, or runtime example;
- add a focused implementation for an existing job;
- document a real run with redacted input, actual output, and limitations;
- improve source attribution, licensing notes, or safety boundaries.

## Before opening a pull request

1. Search existing files, issues, and pull requests for the same change.
2. Keep the change focused on one job, runtime, or factual correction.
3. Explain what changed and what you actually tested.
4. If a model or workflow ran, identify the runtime, model/version, source commit, input, actual output, and failed cases.
5. If you only checked syntax, JSON, file presence, or documentation, label it as a structural check rather than a model run.
6. Use fictional or permissioned data. Remove credentials, private messages, personal data, customer records, wallet details, and proprietary inputs.
7. Keep sending, publishing, spending, deleting, trading, pushing, and merging behind explicit human authorization.

## Pull request details

```text
Job and runtime:
Problem:
Change:
Files changed:
Validation actually performed:
Runtime and model/version (if run):
Source commit:
Redacted input and actual output:
Known limits or failed cases:
Source attribution and license:
```

A prompt pack is not automatically a multi-agent system. A code sketch is not a production deployment. Do not claim performance, users, revenue, or verification that the evidence does not establish.

Improving Build Library source does not publish a Marketplace product. For a ready-to-use product submission, use the [Marketplace seller guide](https://github.com/BotShelfVampire/botshelf/blob/main/docs/sellers.md).
